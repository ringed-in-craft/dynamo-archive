# dynamo/reproducible-release-tarball

**Category:** Build Dependency and Release Management — Release Artifacts · **Objective:** build_or_package, analyze · **Artifact:** single_script_or_program, archive_or_compressed_artifact

## The problem

Seventeen files ship with their corresponding 8-hex-digit integrity markers, generated by a proprietary marker tool that was lost. The agent must infer the marker algorithm and reimplement the release pipeline that produces it.

## What makes it hard

The obvious reading is 'make a reproducible tarball' with the standard `SOURCE_DATE_EPOCH` / `--sort=name` toolkit — which is publicly documented and therefore tests flag recollection, not reasoning. The task was deliberately re-scoped so the deciding element is a non-standard derived marker, not flag trivia.

## How it's verified

Markers are checked against held-out files with pre-computed values, so the algorithm must generalise. Structural probes on the produced archive give diagnostic signal without becoming the pass gate.

## Calibration

Pivoted to data-only (17 I/O pairs, reference binary removed) after the rule-recollection problem was identified. 18 commits, the second-longest iteration history in the archive.
